# Data Model: AI-Powered Career Evolution Features

**Branch**: `002-career-evolution-ai` | **Date**: 2026-05-30
**Phase**: 1 — Derived from `spec.md` Key Entities section

This document defines **additions and modifications** to the existing schema from
`001-ai-study-guide-app/data-model.md`. All existing entities (User, LearningGoal,
LearningPath, Topic, StudySession, DailyPlan, DailyPlanTask, CoachMessage,
PasswordResetToken) are unchanged unless explicitly noted below.

---

## Entity Overview (additions)

```
User
 └── CareerTarget (0..*)       — versioned, all kept; most recent = active
 └── SkillGapReport (0..*)     — one per analysis run; persisted forever
 └── WeeklyReport (0..*)       — one per ISO week; generated by cron
Topic
 └── KnowledgeAssessment (0..1 per calendar day per user)
```

## Schema Modifications to Existing Entities

### Topic (modified)

New column added to support the analytics domain coverage map (FR-006).

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `domain` | TEXT | NULLABLE | AI-inferred technology domain for analytics grouping; null until first analytics load; "Outros" used in UI when null |

**Inference strategy**: Lazily populated on first analytics load via batch `generateObject`
call (see `research.md` Decision 2). Never null-forced in the application — UI falls back to
"Outros" display string while column is null.

**Index**: No index required; analytics query is a GROUP BY over all user's topics, not
a point lookup.

## New Entities

### CareerTarget

The user's defined professional destination. Versioned — each update creates a new row;
all history is retained. Maps to FR-003, US2.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | UUID | PK | Unique identifier |
| `user_id` | UUID | FK → User, NOT NULL | Owner |
| `description` | TEXT | NOT NULL | Free-text career goal description |
| `created_at` | TIMESTAMP | NOT NULL, DEFAULT NOW() | Version timestamp |

**Active version resolution**: `SELECT * FROM career_targets WHERE user_id = $userId ORDER BY created_at DESC LIMIT 1`

**State transitions**: N/A — append-only; no mutations after insert.

**Validation rules**:
- `description` must be non-empty (min 10 chars in Zod schema to prevent placeholder saves)
- No limit on number of versions per user (FR-003)

**Cascade delete**: All rows for `user_id` deleted on account deletion (FR-010).

**Export**: All versions included in JSON export (FR-010) as `careerTargets` array, sorted by `created_at` ascending.

### KnowledgeAssessment

An AI-generated MCQ evaluation for a specific topic, completed by the user. Maps to FR-001, FR-002, US1.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | UUID | PK | Unique identifier |
| `user_id` | UUID | FK → User, NOT NULL | Owner |
| `topic_id` | UUID | FK → Topic, NOT NULL | Topic being assessed |
| `questions` | JSONB | NOT NULL | Array of MCQ questions (see schema below) |
| `score` | INT | NULLABLE, CHECK 0–100 | Computed score after submission; null until submitted |
| `submitted_at` | TIMESTAMP | NULLABLE | When user submitted answers; null = assessment generated but not yet answered |
| `fsrs_modified` | BOOLEAN | NOT NULL, DEFAULT false | Whether FSRS interval was adjusted based on this assessment's score |
| `created_at` | TIMESTAMP | NOT NULL, DEFAULT NOW() | When assessment was generated |

**JSONB `questions` schema**:
```ts
Array<{
  id: string;                           // UUID
  text: string;                         // Question text
  options: { a: string; b: string; c: string; d: string };
  correct: 'a' | 'b' | 'c' | 'd';      // Server-side only; omitted from GET response until submitted
  userAnswer: 'a' | 'b' | 'c' | 'd' | null;
  dimension: 'recall' | 'application' | 'analysis';
}>
```

**Unique constraint**: `(user_id, topic_id, DATE(created_at))` — enforces one assessment per topic per calendar day (FR-001).

**Indexes**:
- `(user_id, topic_id, created_at DESC)` — for same-day check and history queries
- `(user_id, created_at DESC)` — for listing all assessments in export

**State transitions**:
```
generated  → submitted  (user POSTs answers; score computed; FSRS modified)
```
No further transitions — assessments are immutable after submission.

**Side effects on submission (score calculation)**:
1. Compute `score = (correct answers / total questions) × 100`
2. Invoke `applyAssessmentModifier(topic.fsrs_fields, score)`:
   - score ≥ 80: extend `topic.next_review_at` by ×1.25
   - score 50–79: leave FSRS unchanged
   - score < 50: set `topic.next_review_at = NOW() + 3 days`; create extra DailyPlanTask for review within 3 days
3. Set `fsrs_modified = true`
4. Set `submitted_at = NOW()`
5. Invalidate Redis daily plan cache for user

**Same-day re-request logic** (FR-001 edge case):
- On `POST /api/topics/:topicId/assessment`: if a row exists with `DATE(created_at) = TODAY` for this `(user_id, topic_id)`, return existing assessment (including revealed answers if already submitted) — no new AI call.

### SkillGapReport

A persisted output of a single AI-powered gap analysis run. Maps to FR-004, FR-005, US2.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | UUID | PK | Unique identifier |
| `user_id` | UUID | FK → User, NOT NULL | Owner |
| `career_target_id` | UUID | FK → CareerTarget, NULLABLE | The target version used for this analysis; null if target was deleted |
| `career_target_snapshot` | TEXT | NOT NULL | Snapshot of target description at generation time (for display even if target later updated) |
| `generated_at` | TIMESTAMP | NOT NULL, DEFAULT NOW() | Generation timestamp |
| `covered_skills` | JSONB | NOT NULL | Array of skill strings already covered |
| `missing_skills` | JSONB | NOT NULL | Array of critical missing skill strings |
| `suggested_goals` | JSONB | NOT NULL | Array of `{ title: string, rationale: string }` (3–5 items) |
| `topics_count_at_generation` | INT | NOT NULL | Count of completed topics at generation time (used for FR-005 stale-report detection) |

**State transitions**: N/A — append-only; no mutations after insert.

**Stale detection (FR-005)**:
```
IF (current_completed_topics_count - most_recent_report.topics_count_at_generation) >= 10
  THEN prompt user to regenerate
```

**Most-recent report query**: `ORDER BY generated_at DESC LIMIT 1`

**Cascade delete**: All rows for `user_id` deleted on account deletion (FR-010).

**Export**: All reports included in JSON export as `skillGapReports` array.

### WeeklyReport

A system-generated summary for a specific calendar week. Maps to FR-007, FR-008, US4.

| Field | Type | Constraints | Description |
|-------|------|-------------|-------------|
| `id` | UUID | PK | Unique identifier |
| `user_id` | UUID | FK → User, NOT NULL | Owner |
| `week_id` | VARCHAR(8) | NOT NULL | ISO week identifier in `YYYY-Www` format (e.g., `2026-W22`) |
| `generated_at` | TIMESTAMP | NOT NULL, DEFAULT NOW() | When this report was generated |
| `period_start` | DATE | NOT NULL | Monday of the reported week |
| `period_end` | DATE | NOT NULL | Sunday of the reported week |
| `topics_completed` | INT | NOT NULL | Topics completed during the week |
| `study_hours` | NUMERIC(5,2) | NOT NULL | Total study hours (rounded to 2dp) |
| `streak_at_generation` | INT | NOT NULL | User's streak count at generation time |
| `top_domain` | TEXT | NULLABLE | Most-studied domain this week; null if no domain data |
| `weakest_domain` | TEXT | NULLABLE | Domain with least coverage; null if no domain data |
| `ai_insight` | TEXT | NOT NULL | AI-generated insight sentence (or fallback phrase if AI unavailable) |
| `fallback_used` | BOOLEAN | NOT NULL, DEFAULT false | True if AI call failed and fallback phrase was used |
| `email_sent_at` | TIMESTAMP | NULLABLE | When email was sent; null = email not sent (opt-out or delivery failure) |

**Unique constraint**: `(user_id, week_id)` — enforces one report per user per ISO week.

**Index**: `(user_id, period_start DESC)` — for listing most-recent-first in "Relatórios Semanais" page.

**Cron idempotency**: `INSERT ... ON CONFLICT (user_id, week_id) DO NOTHING` — if cron fires twice on the same Monday (retry), no duplicate row is created.

**State transitions**: N/A — append-only; `email_sent_at` is the only post-insert mutation (written after successful email delivery).

**Cascade delete**: All rows for `user_id` deleted on account deletion (FR-010).

**Export**: All reports included in JSON export as `weeklyReports` array.

## Key Query Patterns (new)

### Same-day assessment check
```sql
SELECT * FROM knowledge_assessments
WHERE user_id = $userId
  AND topic_id = $topicId
  AND DATE(created_at AT TIME ZONE $userTimezone) = CURRENT_DATE AT TIME ZONE $userTimezone
ORDER BY created_at DESC
LIMIT 1;
```

### Most-recent career target
```sql
SELECT * FROM career_targets
WHERE user_id = $userId
ORDER BY created_at DESC
LIMIT 1;
```

### Stale gap report detection (FR-005)
```sql
-- Count completed topics since last report
WITH last_report AS (
  SELECT topics_count_at_generation, generated_at
  FROM skill_gap_reports
  WHERE user_id = $userId
  ORDER BY generated_at DESC
  LIMIT 1
),
current_count AS (
  SELECT COUNT(*) AS n
  FROM topics t
  JOIN learning_paths lp ON t.path_id = lp.id
  JOIN learning_goals lg ON lp.goal_id = lg.id
  WHERE lg.user_id = $userId
    AND t.status IN ('complete', 'known')
)
SELECT (current_count.n - last_report.topics_count_at_generation) >= 10 AS should_regenerate
FROM last_report, current_count;
```

### Weekly velocity for analytics
```sql
SELECT
  DATE_TRUNC('week', ss.studied_at) AS week_start,
  COUNT(DISTINCT ss.topic_id) AS topics_completed,
  SUM(ss.duration_minutes) / 60.0 AS hours_studied
FROM study_sessions ss
WHERE ss.user_id = $userId
  AND ss.studied_at >= CURRENT_DATE - INTERVAL '8 weeks'
GROUP BY week_start
ORDER BY week_start ASC;
```

### Domain coverage for analytics
```sql
SELECT
  COALESCE(t.domain, 'Outros') AS domain,
  COUNT(*) FILTER (WHERE t.status IN ('complete', 'known')) AS completed_count,
  AVG(ss.confidence_rating) AS avg_confidence,
  COUNT(*) FILTER (WHERE t.next_review_at <= NOW()) AS due_for_review
FROM topics t
JOIN learning_paths lp ON t.path_id = lp.id
JOIN learning_goals lg ON lp.goal_id = lg.id
LEFT JOIN study_sessions ss ON ss.topic_id = t.id
WHERE lg.user_id = $userId
GROUP BY domain
ORDER BY completed_count DESC;
```
