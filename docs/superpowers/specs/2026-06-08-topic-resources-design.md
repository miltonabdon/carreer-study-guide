# Design: AI-Generated Topic Resources

**Date**: 2026-06-08
**Status**: Approved
**Scope**: Enrich each learning path topic with an AI-generated explanation, YouTube video link, and article/documentation link, surfaced in the existing notes section of `TopicNode`.

---

## Problem

Topics in learning paths currently contain only a title, description, complexity rating, and estimated time. Users have to search externally for every resource. This friction slows learning and defeats the goal of a guided, self-contained study experience.

---

## Solution Overview

Extend `generateLearningPath` so that each generated topic includes three new resource fields: a YouTube video URL, an article/documentation URL, and a contextual explanation written for a software architect. These fields are persisted in the `topics` table and displayed read-only in the existing notes panel of `TopicNode`, above the user's own editable notes.

---

## Data Model

### Schema changes — `topics` table

Two new nullable columns (no NOT NULL, no default — zero impact on existing rows):

| Column | SQL type | Drizzle field | Description |
|---|---|---|---|
| `explanation` | `text` | `explanation` | 2–4 paragraphs in pt-BR explaining the topic, generated by AI |
| `article_url` | `text` | `articleUrl` | URL to official docs or quality technical article |

`resource_url` already exists and will now be pre-populated with a YouTube URL by the AI.

**Migration**: `ALTER TABLE topics ADD COLUMN explanation text, ADD COLUMN article_url text`

No backfill required. Existing topics have null values and the UI handles that gracefully.

---

## AI Generation

### `generateLearningPath` changes

The Zod topic schema gains three optional fields:

```ts
resourceUrl: z.string().url().optional(),
articleUrl: z.string().url().optional(),
explanation: z.string().optional(),
```

The prompt instructs the AI to populate these for every topic:

- **`resourceUrl`**: YouTube video from a trusted channel (freeCodeCamp, Fireship, Traversy Media, Tech With Tim, Coding With Lewis, etc.) directly relevant to the topic title and technology stack.
- **`articleUrl`**: Official documentation or quality article (official project docs, dev.to, Medium engineering blogs, CSS-Tricks, etc.).
- **`explanation`**: 2–4 paragraphs in pt-BR. Structure: (1) central concept and why it matters, (2) how it fits into software architecture / analogy with distributed systems or design patterns, (3) what to pay attention to when practicing it. Tone: direct, professional, assumes a senior engineer reading.

### Mock data (`mockLearningPath`)

The mock returns fixed, real-world URLs per topic so local development with `MOCK_AI=true` shows the full UI. Example for "Fundamentos e Conceitos Base":
- `resourceUrl`: `https://www.youtube.com/watch?v=<real-video-id>`
- `articleUrl`: `https://docs.python.org/3/tutorial/`
- `explanation`: a fixed paragraph stub in pt-BR

### Error handling

`resourceUrl`, `articleUrl`, and `explanation` are all optional in the schema. If the AI omits any field or returns an invalid URL, the field is stored as null and the UI silently skips that section. No validation error, no blocking.

---

## UI — `TopicNode` notes panel

When the user opens the notes panel (StickyNote button), a "Conteúdo base" section appears **above** the editable fields, but **only when at least one of `explanation` or `articleUrl` is non-null**.

### Layout

```
┌─────────────────────────────────────────────────┐
│ 📖 Explicação                    [IA] label      │
│  Paragraph 1…                                    │
│  Paragraph 2…                                    │
│                                                  │
│ 🔗 Artigo / Documentação                         │
│  [clickable link → opens in new tab]             │
├──────────────────────────────────────────────────┤
│ Resource URL  [input, pre-filled with YouTube]   │
│ Notes         [textarea, user-owned]             │
│                              [Cancelar] [Save]   │
└──────────────────────────────────────────────────┘
```

### Behaviour rules

- `explanation` block: read-only text with a subtle background and a small "Gerado pela IA" badge. Not editable.
- `articleUrl` block: rendered as a clickable `<a target="_blank">` link. Not editable.
- `resourceUrl` (YouTube): pre-filled by the AI in the existing editable input. The user can overwrite it.
- `notes`: fully editable by the user, unchanged.
- If both `explanation` and `articleUrl` are null, the "Conteúdo base" section is hidden entirely — no empty state shown.
- The section is also hidden when the topic is `locked` (the notes panel is not shown at all for locked topics).

---

## Out of Scope

- Retroactive enrichment of existing paths (only new/regenerated paths get resources).
- Editing or regenerating the AI explanation independently per topic.
- Multiple videos or articles per topic.
- Validation that AI-generated URLs resolve successfully.
